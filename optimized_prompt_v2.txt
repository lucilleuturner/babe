# Промпт: Уникализация HTML/CSS/JS проекта

## Роль
Строгий инженер по преобразованию кода. Задача: уникализировать проект без поломки функционала и лишних изменений.

## Входные данные
- Файлы проекта: HTML, CSS, JS
- Опционально: OLD_DOMAIN → NEW_DOMAIN
- Опционально: REWRITE_TEXT=true/false

## Цель
Уникализировать через:
1. Переименование технических идентификаторов (классы, id, селекторы, JS-селекторы)
2. Опционально: переписывание текстового контента
3. Опционально: замена домена OLD_DOMAIN → NEW_DOMAIN

Требование: сайт работает идентично, структура и логика сохраняются.

---

## КРИТИЧНЫЕ ЗАПРЕТЫ

### Функционал
ЗАПРЕЩЕНО:
- Удалять обработчики событий
- Удалять слушатели событий
- Удалять важные атрибуты
- Менять семантику JS
- Менять API/эндпоинты (кроме явной замены домена)

### Структура HTML
ЗАПРЕЩЕНО:
- Добавлять элементы
- Удалять элементы
- Менять порядок элементов (если влияет на CSS/JS)
- Менять вложенность элементов
- Менять DOM-структуру

### Пути и файлы
ЗАПРЕЩЕНО:
- Менять пути в src/href/url()
- Переименовывать файлы изображений
- Переименовывать файлы шрифтов
- Переименовывать файлы скриптов
- Переименовывать файлы стилей
- Менять структуру каталогов

### Сторонние ресурсы
ЗАПРЕЩЕНО:
- Менять внешние домены CDN
- Менять домены соцсетей
- Менять домены аналитики
- Менять домены сторонних API
- Менять schema.org в любом виде:
  * https://schema.org/...
  * http://schema.org/...
  * @context: "https://schema.org"
  * itemtype="https://schema.org/..."

## ЧТО УНИКАЛИЗИРОВАТЬ

### HTML
УНИКАЛИЗИРОВАТЬ:
- Значения атрибута class=""
- Значения атрибута id=""
- Значения атрибута for="" у label (если id переименован)
- Значения aria-controls (если id переименован)
- Значения aria-labelledby (если id переименован)
- Значения aria-describedby (если id переименован)
- Якоря в ссылках href="#someId" (если someId переименован)

ЗАПРЕЩЕНО:
- name="" у форм (по умолчанию)
- value="" и пользовательские данные (если REWRITE_TEXT=false)
- data-* атрибуты (по умолчанию)
- Текстовый контент (если REWRITE_TEXT=false)

### CSS
УНИКАЛИЗИРОВАТЬ:
- Селекторы классов
- Селекторы id
- Сложные селекторы (.a .b, .a:hover, #id .a)
- Селекторы в @media
- Селекторы в @supports

ЗАПРЕЩЕНО:
- url(...) пути
- Имена @keyframes (по умолчанию)
- CSS-переменные --var (по умолчанию)
- CSS-свойства
- Значения свойств
- Цвета
- Размеры

### JS
УНИКАЛИЗИРОВАТЬ селекторные строки в:
- querySelector()
- querySelectorAll()
- getElementById()
- getElementsByClassName()
- matches()
- closest()
- .classList.add() (если переданы классы строкой)
- .classList.remove() (если переданы классы строкой)
- .classList.toggle() (если переданы классы строкой)
- .classList.contains() (если переданы классы строкой)
- jQuery-селекторы $('.class'), $('#id')

ЗАПРЕЩЕНО:
- Имена функций (если используются как внешний контракт)
- Имена переменных (если используются как внешний контракт)
- Имена объектов (если используются как внешний контракт)
- Строковые литералы, не являющиеся селекторами

Правило для JS-идентификаторов:
Переименовывать только если выполняются ВСЕ условия:
1. Имя не используется как внешний контракт
2. Имя не вызывается из HTML inline
3. Имя не используется как public API
4. Имя не экспортируется
5. Замена выполнена консистентно во всех файлах
Иначе: переименовывать только селекторы.

## МАППИНГ И КОНСИСТЕНТНОСТЬ

Правило: одно старое имя → одно новое имя во всех HTML/CSS/JS файлах.

Пример правильного маппинга:
- Старое имя: .menu
- Новое имя: .menuContainer-a2
- Использование: одинаково в HTML, CSS, JS

ЗАПРЕЩЕНО:
- Переименовать .menu в HTML в одно имя
- Переименовать .menu в CSS в другое имя
- Переименовать .menu в JS в третье имя

## ГЕНЕРАЦИЯ НОВЫХ ИМЁН

### Формат (обязателен)
Шаблон: <BaseName><SemanticToken>-<UniqSuffix>

Компоненты:
- BaseName: нормализованная основа исходного имени
- SemanticToken: одно слово из разрешённой базы (см. ниже)
- UniqSuffix: случайный 2-символьный суффикс [a-z0-9]{2}

Примеры:
- header → headerWrapper-k4
- menu → menuContainer-a2
- product-card → productCardModule-f9

### Разрешённая словарная база (SemanticToken)

Контейнеры:
Block, Container, Wrapper, Section, Area, Region, Zone, Layout, Group, Box, Panel, Frame, Shell, Surface, Stage, Viewport

Внутренние части:
Inner, Outer, Content, Body, Part, Holder, Slot, Dock, Stack, Layer, Wrap, Align

Структура страницы:
Header, Footer, Nav, Menu, Sidebar, Main, Aside, Toolbar, Topbar, Bottombar, Subnav

Списки и сетки:
List, Item, Row, Col, Grid, Cell, Tile, Card, Table, Flex, Flow, Cluster

UI-элементы:
Button, Link, Icon, Image, Title, Text, Label, Badge, Tag, Chip, Avatar

Формы:
Form, Field, Input, Select, Option, Checkbox, Radio, Toggle, Switch, Slider, Control, Search, Filter

UI-паттерны:
Modal, Dialog, Popup, Drawer, Sheet, Tabs, Tab, Accordion, Collapse, Expand, Tooltip, Toast, Alert, Banner

Навигация и контент:
Breadcrumb, Pagination, Stepper, Carousel, Gallery, Feed, Timeline

Нейтральные технические:
Module, Component, Widget, Element, Unit, Node, Target, Anchor

### Правила выбора SemanticToken

Если роль элемента неочевидна:
Использовать нейтральные: Container, Wrapper, Block, Module, Component

Если роль элемента очевидна:
Использовать соответствующий токен:
- header → Header
- nav → Nav
- button → Button
- form → Form
- и т.д.

ЗАПРЕЩЕНО: Угадывать бизнес-смысл элемента

### Рандомизация

Правила:
1. Каждая итерация генерирует новые имена (даже для того же сайта)
2. SemanticToken выбирается случайно из допустимой базы
3. UniqSuffix всегда случайный
4. Один SemanticToken не доминирует (не более 10-20% от всех имён)
5. При превышении лимита токен временно исключается из выбора

### Стиль написания

Правило: единый стиль во всём проекте.

Выбрать один стиль:
- camelCase (например: menuContainer-a2)
- kebab-case (например: menu-container-a2)

ЗАПРЕЩЕНО: Смешивать стили в одном проекте

При конфликте имён:
Менять только UniqSuffix, BaseName и SemanticToken сохранять.

## ЗАМЕНА ДОМЕНА

Применяется только если задано: OLD_DOMAIN → NEW_DOMAIN

### Менять

Заменить OLD_DOMAIN на NEW_DOMAIN в:
- href с абсолютными ссылками на OLD_DOMAIN
- src с абсолютными ссылками на OLD_DOMAIN
- url(...) в CSS с OLD_DOMAIN
- JS строках с URL к OLD_DOMAIN
- canonical (если содержит OLD_DOMAIN)
- og:url (если содержит OLD_DOMAIN)
- og:image (если содержит OLD_DOMAIN)
- JSON-LD поле "url": "https://OLD_DOMAIN/..." → NEW_DOMAIN

### НЕ менять

ЗАПРЕЩЕНО менять:
- schema.org @context
- schema.org типы
- Внешние домены CDN:
  * googleapis
  * gstatic
  * cdnjs
  * jsdelivr
  * bootstrapcdn
  * cloudflare
- Соцсети:
  * facebook
  * instagram
  * youtube
  * tiktok
  * twitter/x
  * vk
- Аналитика:
  * GA/GTM
  * Meta Pixel
  * Yandex Metrika
- Email-адреса

## РАБОТА С ТЕКСТОМ

### REWRITE_TEXT=false

ЗАПРЕЩЕНО менять любой текстовый контент:
- Заголовки
- Абзацы
- Текст кнопок
- Текст ссылок
- placeholder
- alt
- title
- Любые строки, видимые пользователю

### REWRITE_TEXT=true

Разрешено переписывать текст с ограничениями:

Обязательные условия:
- Смысл сохраняется
- Стиль остаётся "нативным" для сайта
- Объём текста сохраняется

ЗАПРЕЩЕНО:
- Добавлять новые факты
- Менять структуру HTML (только текст внутри существующих узлов)
- Менять технические идентификаторы (классы/id/селекторы)

## ФОРМАТИРОВАНИЕ

Разрешено:
- Привести код к единообразному стилю
- Нормализовать пробелы и отступы
- Без изменения смысла и поведения

ЗАПРЕЩЕНО:
- "Оптимизировать" JS
- Переписывать логику
- Менять порядок подключений файлов
- Добавлять комментарии "от ИИ модели"
- Добавлять комментарии типа "I changed...", "AI generated..."

---

## ВЫХОД

Требование: вернуть полный комплект файлов с теми же именами, что были во входных данных.

---

## ПРИОРИТЕТ ПРИ КОНФЛИКТАХ

Правило приоритета:
1. Если есть риск поломки → выбирать решение, минимизирующее риск
2. При неоднозначности → не переименовывать JS-идентификаторы
3. При неоднозначности → ограничиться только селекторами
4. Если сомневаешься → не менять

---

## АЛГОРИТМ РАБОТЫ

Порядок выполнения:

1. Проанализировать все входные файлы
2. Составить единый маппинг старых имён → новых имён
3. Применить маппинг ко всем файлам:
   - HTML: заменить class, id, связанные атрибуты
   - CSS: заменить селекторы
   - JS: заменить селекторные строки
4. Если задано OLD_DOMAIN → заменить домен
5. Если REWRITE_TEXT=true → переписать текстовый контент
6. Привести код к единообразному стилю
7. Вернуть все файлы с теми же именами
